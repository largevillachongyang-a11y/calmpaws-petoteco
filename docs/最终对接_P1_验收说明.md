# 最终对接 P1 验收说明（FCM 推送）

> **预览**：https://largevillachongyang-a11y.github.io/calmpaws-petoteco/  
> **前提**：已完成 P0（登录 + 绑定 `collar_001`）  
> **API**：`POST /api/user/register_fcm`

---

## 本阶段做了什么（P1）

- 添加 `firebase_messaging`，`FcmService` 初始化 + `onTokenRefresh` 自动重注册
- 登录 / 进入主页后调用 `POST /api/user/register_fcm`（Bearer）
- 前台推送 → 应用内通知中心 + Android/iOS 本地通知栏
- Web：`web/firebase-messaging-sw.js`；`index.html` 保留 FCM SW、清除旧 Flutter SW

**Web 限制**：需在 `EnvironmentConfig.fcmWebVapidKey` 填入 Firebase Console 的 Web Push VAPID Key，否则 Web 预览**无法**拿到 token（Android/iOS 不受影响）。

---

## 验收步骤

### 1. FCM Token 注册

1. 登录并绑定设备，进入 Dashboard。
2. DevTools → Network，应看到 `POST /api/user/register_fcm` → **200**。
3. Request Body 含 `fcm_token`、`device_type`（web / android / ios）。

### 2. 前台推送（App 打开时）

请服务器向该用户发一条测试推送（含 `notification.title/body`，可选 `data.type`）。

- **通知中心**（铃铛图标）出现新条目。
- **Android/iOS**：系统通知栏也有横幅（需已授权通知权限）。
- **Web 预览**：通知中心有记录；系统通知依赖浏览器 + SW，本地通知为 no-op。

### 3. Token 刷新

- 重新安装 App 或清除数据后登录，应再次 `register_fcm`。
- `onTokenRefresh` 触发时也会自动重注册（无需手动操作）。

### 4. 调试日志（Debug 构建）

Console 关键字：

- `[FCM] 初始化完成`
- `[FCM] 已注册 token`
- `[UserDeviceAPI] FCM token 已注册`
- Web 无 VAPID：`Web 端需配置 fcmWebVapidKey 才能获取 FCM token`
