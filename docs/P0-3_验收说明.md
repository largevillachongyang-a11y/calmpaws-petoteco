# P0-3 验收说明 — `/api/history` 数据层

> 对应阶段：实现 `fetchHistory` + 历史数据模型 + Provider 缓存（图表重写属 P0-4）

## 改了什么

- 新增 `lib/models/history_models.dart`：
  - `HistoryPoint`（含 `localDateTime` / `dateAsDateTime` 时区辅助）
  - `HistorySummary`
  - `HistoryResponse`（含 `empty()` / `error()` 工厂）
  - `HistoryRange`（`24h` / `7d` / `30d`）
- `ServerApiService.fetchHistory(range)`：GET `/api/history/<device_id>?range=...&key=...`
- 防御：空 body、204、`points: []`、null 字段、非 200 均不崩溃
- `PetHealthProvider.loadServerHistory()`：连接真实服务器时自动拉取三档历史并缓存
- 暴露 getter：`history24h` / `history7d` / `history30d`、`onlineMinutes24h`、`serverHistoryError`

## 如何测试（GitHub Pages 预览）

1. 打开 https://largevillachongyang-a11y.github.io/calmpaws-petoteco/ 并 **Ctrl+F5** 强刷
2. 登录后进入 **健康 Dashboard**
3. 确认设备栏 **Connected**（真实服务器模式默认开启）
4. 页面加载后 APP 会自动请求 history（无需手动操作）

> **本阶段图表 UI 仍是旧版 14 天 mock**；验收重点在 Network 与 Provider 数据，不靠图表外观判断。

## 如何测试（浏览器 DevTools → Network）

1. F12 → **Network**，勾选 **Preserve log**
2. 刷新 Dashboard，过滤 `history`
3. 应看到 **3 条** 请求（并发）：

| 请求 | 预期 |
|------|------|
| `GET .../api/history/collar_001?range=24h&key=...` | 200，JSON 含 `points` + `summary` |
| `GET .../api/history/collar_001?range=7d&key=...` | 200，含 `date` 字段的日汇总 |
| `GET .../api/history/collar_001?range=30d&key=...` | 200 |

4. 点开 **24h** Response，确认：
   - `points[].time` 为 UTC unix 秒
   - `points[].anxiety_score`、`dominant_state`、`states` 存在
   - `summary.online_minutes` 存在（监测时长，P0-4 图表底部将使用）

5. 点开 **7d** Response，确认 `points[].date` 为 `YYYY-MM-DD` 格式

6. **无数据时**：`points: []` 仍应 200，APP 不白屏、不崩溃

## 预期行为

| 场景 | 预期 |
|------|------|
| 连接真实服务器 | 自动触发 3 条 history 请求 |
| 服务器返回空 `points` | APP 正常显示，不崩溃 |
| Mock 数据源 | 不请求 history（`loadServerHistory` 跳过） |
| 网络超时 | `serverHistoryError` 有提示，不影响 status 轮询 |
