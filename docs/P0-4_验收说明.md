# P0-4 验收说明 — 重写 StressChartCard

> 对应阶段：三档 Tab + 服务器历史数据 + dominant_state 染色 + 监测时长

## 改了什么

- 新增 `lib/theme/state_colors.dart`：7 种 `dominant_state` → 颜色 + 中英文图例
- **重写** `StressChartCard`：
  - Tab：**24小时 / 7天 / 30天**
  - 24h：**折线图**，X 轴本地时区 0:00–24:00，按状态分段染色，大间隔断开
  - 7d/30d：**柱状图**，无数据天灰色空柱，有数据柱按 `dominant_state` 染色
  - 底部：**监测时长**（24h 用 `summary.online_minutes`；7d/30d 用 `days_with_data/days_total` + `online_hours_total`）
  - 均值/峰值摘要 chips、7 状态图例、刷新按钮
- 数据来源：`PetHealthProvider.history24h/7d/30d`（不再用 14 天 mock 画此卡）
- i18n：更新 `app_strings.dart` 图表相关文案

## 如何测试

### 1. UI 验收（Dashboard）

1. 登录 → **健康 Dashboard** 向下滚动到 **焦虑历史** 卡片
2. 确认标题为「焦虑历史」，副标题含「服务器数据」
3. 点击 Tab 切换 **24小时 / 7天 / 30天**，图表形态应变化：
   - 24h → 折线 + 彩色点
   - 7d/30d → 柱状图
4. 底部应显示监测时长，例如：
   - 24h：`今日已监测 X 小时 Y 分钟`
   - 7d：`监测 A/B 天 · 累计 C 小时`
5. 图例行应显示 7 种状态颜色（平静、睡眠、玩耍…）
6. 点右上角 **刷新** → Network 应重新请求对应 `range` 的 history

### 2. Network 对照

过滤 `history`，确认三档数据与 UI 一致：

| Tab | 请求 | UI 应对齐 |
|-----|------|-----------|
| 24小时 | `range=24h` | 折线点数 ≈ `points.length`；颜色随 `dominant_state` |
| 7天 | `range=7d` | 7 根柱（无数据天灰色）；柱色 = 该天 `dominant_state` |
| 30天 | `range=30d` | 30 根柱 |

### 3. 染色验收

在 24h Response 中找不同 `dominant_state` 的点，折线段/点颜色应与图例一致：

| dominant_state | 颜色 |
|----------------|------|
| calm | 绿 |
| pacing | 黄 |
| stressed | 橙 |
| shivering | 红 |

### 4. 空数据 / 异常

| 场景 | 预期 |
|------|------|
| `points: []` | 卡片中央「暂无数据」，不崩溃 |
| Mock 数据源 | 提示「请连接服务器查看历史曲线」 |
| 加载中 | 显示 loading 圈 |
