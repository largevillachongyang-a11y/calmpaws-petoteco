## 四、当前阻塞：history 401（需服务器）

### 4.1 现象

Network 中以下请求返回 **401 Unauthorized**：

```
GET https://api.myvideotest2026.top/api/history/collar_001?range=24h
GET ...?range=7d
GET ...?range=30d
```

Header 已带：`Authorization: Bearer <Firebase ID Token>`

`GET /api/status/collar_001` 与 `GET /api/user/devices` 正常。

### 4.2 请服务器同事核对

1. **Firebase Admin SDK** 是否已配置且能验证 ID Token（项目 `petoteco-5e807`）
2. **`/api/history`** 是否已迁移到 Bearer 鉴权（不是仍只认 `?key=`）
3. 该 Firebase 用户是否已通过 **`POST /api/user/bind_device`** 绑定 `collar_001`
4. Bearer 模式下是否校验「用户 ↔ 设备」绑定关系（未绑定应 **403** 而非 401）
5. 401 响应 body 具体内容（便于区分 token 无效 vs 接口未改）

### 4.3 服务器自测 curl（文档 §七）

```bash
# 1. 用 Firebase 登录拿到 idToken 后：
curl -s -H "Authorization: Bearer <ID_TOKEN>" \
  https://api.myvideotest2026.top/api/user/devices

# 2. 绑定
curl -s -X POST -H "Authorization: Bearer <ID_TOKEN>" \
  -H "Content-Type: application/json" \
  -d '{"device_id":"collar_001","device_key":"calmpaws_secret"}' \
  https://api.myvideotest2026.top/api/user/bind_device

# 3. history（当前 APP 卡在这里）
curl -s -H "Authorization: Bearer <ID_TOKEN>" \
  "https://api.myvideotest2026.top/api/history/collar_001?range=24h"
```

**期望**：步骤 3 返回 **200** 或 **204**，不是 401。
